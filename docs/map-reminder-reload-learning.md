# Remembering map follow-up in this tab

16 November 2026.

After an applied cross-stay move, the map follow-up now survives a reload in the same browser tab for up to 24 hours. It stores only the account owner, trip and activity/destination/day identifiers, and the time of the reminder. It does not store map records, activity content, or a plan snapshot. Dismissal, signing out, or starting a new trip clears it. A later rebalance preserves earlier reminders and merges new cross-stay moves, updating an item if it moved again.

Follow-up: an applied move within the same stay now updates an existing reminder to its new day, provided its old destination and day match the applied response. An explicitly dropped matching activity is removed from the reminder. Preview responses never advance it. A signed-in browser check now covers a cross-stay move, a second move within the destination, reload and opening the current editor.

Later manual activity edits also update existing reminder pointers from the successfully saved account snapshot; removing or resolving a tracked activity removes its pointer. Unsaved edits do not rewrite session storage. This does not create reminders for unrelated manual edits or restore old place data. In the signed-in browser, a temporary cross-stay move was followed by moving its day through the activity editor; the reminder changed after account saving, survived reload and cleared after the test activity was removed and saved. Multiple-item reconciliation has unit coverage; failure and offline saving were not exercised in this walkthrough.

On reopening an account trip, the app checks the owner and trip and resolves each item against the current saved draft. Removed, moved again, completed or skipped activities are omitted; an already linked item cannot reopen a stale location action. A remaining unlinked activity keeps the reminder available even if another was linked. The reminder is navigation only: choosing and saving a location still requires an explicit action. It does not make a reservation or verify journeys.

The tradeoff is a tab-scoped, temporary convenience rather than durable cross-device notifications. A reminder may be lost if storage is unavailable, the tab closes, it expires, or the saved activity no longer matches its destination and day. No plan data is reconstructed from it.
